# 구현 결정

- 화면 톤은 SRS 8.3이 아니라 규정관리 시스템(흰 배경, 모서리 0, `#2f6fed`, SCoreDream)을 따른다.
- 저장소 루트는 `bojik/`가 아니라 이 폴더다.
- 회의자료와 메모의 기준은 서버다. Google Drive와 Apps Script는 화면 동작에 쓰지 않는다. 서버에 연결하지 못하면 예전 자료를 보여 주지 않고 오류만 보여 준다.
- 자료 파일은 `/var/www/depthm-data/materials`, 회의·계정·메모는 그 옆 `depthm.sqlite`다. 운영에서는 개발 폴더로 바꾸지 않는다.
- 폴더 이름은 `yy.mm.dd.`이고, 같은 날짜의 회의는 회의 ID로 구분한다. Admin은 경로를 입력하지 않는다.
- 보직자는 직위·이름을 클릭하고 관리자는 `admin으로 들어가기`를 클릭해 즉시 로그인한다. 비밀번호 입력·변경·초기화와 계정·주소 잠금 기능은 제거한다. 사번은 선택 사항이며 로그인 조건이 아니다.
- 기존 SQLite의 비밀번호·잠금 열과 기록은 호환성과 배포 되돌리기를 위해 남겨 두되 로그인에 사용하지 않는다. 기존 비밀번호 변경 대기 상태와 잠금 기록은 접속을 막지 않는다. 계정 ID를 유지하므로 기존 메모도 그대로 연결된다.
- 로그인하기 전에는 보직 목록만 받는다. 자료와 메모 API는 선택한 계정의 세션으로 호출한다. 로그인 뒤에는 회의 날짜의 PDF만 미리 받는다.
- 메모는 사용자 ID, 회의 ID, 파일 ID로 데이터베이스에 저장한다. 내려받을 때만 그 계정의 메모를 원본에 입힌다. 원본 파일은 수정하지 않는다.
- 화면은 `https://depthm.yeonsung.ac.kr/` nginx가 `web/dist`를 제공한다. Firebase Hosting은 쓰지 않는다.
- 서버에서 한 번 `sudo bash deploy/install-server-hook.sh`를 실행한 뒤의 `git pull`은 화면 빌드, 문서 루트 반영, 필요하면 API 재시작을 한다. 운영 SQLite와 회의자료는 그 과정에서 복사하거나 지우지 않는다. 푸시만으로는 화면이 바뀌지 않는다.
- 로그인 뒤 자료 목록은 그 접속에서 한 번 받는다. 회의 10분 전·5분 전·1분 전 자동 확인은 하지 않는다. 관리자가 자료를 올리거나 전체새로고침을 하면 열어 둔 화면이 약 30초 안에 목록을 다시 받는다. 화면이 숨겨져 있으면 그 신호를 확인하지 않고, 다시 보이면 바로 확인한다. 받아 둔 PDF는 90일이 지나면 지우고 메모는 남긴다.
- 전체 회의자료는 메일이 아니라 이 기기로 내려받는다. 그 계정의 메모가 입혀진 PDF가 압축에 들어간다.
- 자료 트리의 다운로드 상태 아이콘과 변경 알림 설정 버튼은 표시하지 않는다. 들여쓰기와 파일 앞 빈 공간을 줄여 파일명을 넓게 표시한다. 변경 알림은 회의자료관리의 파일별 버튼으로 설정하고 서버에 저장한다.
- 새 별첨은 대괄호 다음의 기획·교무·입학·학생·산학·행정 순서와 같은 부서 안의 자연 오름차순으로 업로드 시 자동 정렬한다. 수동 정렬 후에는 저장한 순서를 우선하고 추가 파일은 맨 뒤에 놓는다. 화면은 서버의 정렬 값을 따르며 이름으로 다시 정렬하지 않는다. 변경 전부터 있던 별첨은 기존 저장 순서를 보존한다.
